# FortressArch package repository

This folder is served by GitHub Pages as a real pacman repository.

Once GitHub Pages is enabled for this repo (Settings -> Pages -> Deploy
from branch -> main -> /docs), everything in this folder becomes
reachable at:

https://mthepro10.github.io/FortressArch/repo/

That means an installed FortressArch system can subscribe to it exactly
like any other pacman repo, and future updates to fortressarch-selfheal
arrive through plain `sudo pacman -Syu`, no reinstall needed.

## What goes here

- fortress-guard-*.pkg.tar.zst
- fortressarch-selfheal-*.pkg.tar.zst
- fortressarch.db.tar.gz (generated by repo-add, do not edit by hand)
- fortressarch.files.tar.gz (generated by repo-add, do not edit by hand)

Use packaging/publish-update.sh to add a new package version here
correctly.

## Honest security note

This repo currently uses `SigLevel = Optional TrustAll`, meaning
packages are not GPG-signed and pacman will not verify who published
them. Anyone who could tamper with this GitHub Pages content in transit
or at the source could push a malicious update, and an installed system
would accept it. For a project centered on security, this is a real gap,
not a solved problem. Proper GPG package signing is the correct fix, but
it requires generating and safely managing a signing key, which has not
been done here.
